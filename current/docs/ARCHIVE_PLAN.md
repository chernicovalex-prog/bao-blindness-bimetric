# Схема архивирования старых версий репозитория

Статус: схема предъявлена для review в ветке `prerelease/r28-review`; фактические перемещения ещё не выполнены.

## Целевая структура

```
README.md                 # актуальная точка входа и ссылки
LICENSE
current/                  # только текущий предрелиз/рабочая версия
archive/
  <точное_имя_версии_1>/  # старая версия целиком
  <точное_имя_версии_2>/  # без перезаписи и смешивания версий
```

## Обязательная связь статьи и кода

| Статья | Связанный код | Как архивировать |
|---|---|---|
| v21.5 | v10.6 | Сохранять как одну версионную пару, не смешивать с более поздним кодом |
| v21.6 | v10.6 | Та же исполняемая линия; отдельная версия статьи, тот же код v10.6 |
| v28.0 / v28.0.1 | v13.3 | Сохранять вместе как соответствующую documentary source archive; не обещать автоматическую полную сборку без отдельной проверки |

Если код используется двумя статьями, его нельзя бездумно дублировать или заменять: сохраняется один проверенный архивный экземпляр, а в README каждой пары указывается точная связь и SHA-256.

## Правила перемещения

1. Сначала получить фактический список корня репозитория и определить версию каждого файла/папки, не угадывать по дате.
2. Для каждого старого объекта записать `old path → archive/<version>/...` и SHA-256 содержимого.
3. Не удалять и не перезаписывать исторические файлы. Одноимённые объекты с разным содержимым получают разные archive-папки.
4. После перемещения повторно проверить SHA-256, присутствие, ссылки README и публичные entry points.
5. Не переносить в `current/` промежуточные логи, внутренние доказательства или blind-isolation материалы.
6. Все перемещения выполняются как одна ревьюируемая операция после предъявления фактической карты. Ничего не перемещать по неполному списку.

## Фактическая карта текущего корня

`REPO_ARCHIVE_MAP.tsv` содержит 16 старых root-объектов с их текущими GitHub blob SHA, размерами, целевыми путями и связями статья↔код. Текущие `bimetric/`, `probes/`, `tests/`, `data/`, `verification/`, `.github/` и действующие metadata в эту карту не включены и не должны перемещаться автоматически.

## Текущее ограничение

Подключение к репозиторию есть, и карта находится в review-ветке. Бинарные исторические файлы не передаются через текстовый интерфейс: перемещение всей карты должно быть выполнено отдельной Git-операцией с сохранением истории. Эта схема не разрешает перемещать локальные защищённые проектные файлы по аналогии.
